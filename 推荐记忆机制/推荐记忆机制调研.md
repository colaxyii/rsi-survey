## 一、你提到的那三篇（都已定位）

**MSN: A Memory-based Sparse Activation Scaling Framework for Large-scale Industrial Recommendation** — [2602.07526](https://arxiv.org/abs/2602.07526)，2026-02。动机是稀疏激活（MoE）虽然省算力但内存访问贵、专家少导致个性化弱。做法是维护一个**大参数化记忆**，动态检索个性化表示、通过 memory gating 注入下游特征交互。这里"记忆"是**模型的参数化存储**，解决的是容量/成本的 scaling 问题。

**Sample Is Feature: Beyond Item-Level, Toward Sample-Level Tokens for Unified Large Recommender Models** — [2604.15650](https://arxiv.org/abs/2604.15650)，RecSys 2026，作者 Shuli Wang 等（你说是美团，作者阵容与美团推荐团队一致；arXiv 元数据本身不带机构）。它把工业推荐的 scaling 拆成两条线：**样本信息 scaling** 和**模型容量 scaling**，并指出前者只把历史交互的一小部分编码成 token，丢掉了样本级、时变的上下文特征。于是主张把整个样本 token 化。

**Self-Evolving Memory for Generative Recommendation** — [2609.15598](https://arxiv.org/abs/2609.15598)，CIKM'26，Xinyu Lin 等（人大）。这篇的结论对你的思考最关键：持续用流式交互**直接更新共享自回归参数**会触发 **evolution conflict**——不同用户的异质偏好漂移在同一个共享参数空间里被优化，主流行为模式会逐渐主导演化过程，长尾模式被忽视。他们的解法是**把演化放在记忆里而不是共享参数里**。这几乎就是你说的"保留记忆，但不让记忆变成策略本身"的推荐版表述。

## 二、推荐领域的记忆脉络（这次检索到的）

**第一代：把历史当特征（2017–2020）。** DIN/DIEN 那套把历史行为做成 attention 特征；长序列走检索路线（SIM/ETA/TWIN/SDIM）；显式记忆网络（MIMN 的 user interest memory、RUM）用外部 memory 存长期兴趣。共同点：**记忆 = 可检索的特征缓存**，用完即弃，不承担决策职责。（这一段是领域背景，我这次没有逐篇复核原文。）

**第二代：长序列的压缩与缓存（2026 仍在爆发）。** 这是今年最密集的一支：

- [ChronicleRec](https://arxiv.org/abs/2609.12375) 用**时间锚定 token** 预训练做 lifelong user modeling，理由是逐候选检索会把长序列建模和打分耦合在一起、重复在线开销
- [SITA](https://arxiv.org/abs/2608.03692) 语义兴趣 token 做 target-aware 压缩
- [SequenceO1](https://arxiv.org/abs/2609.08443) 100K 超长序列 + low-rank caching，已在工业部署
- [MuSeR](https://arxiv.org/abs/2609.23677) 多兴趣
- [**SinkRec**](https://arxiv.org/abs/2606.09888) 提出 **semantic state sink**——线性注意力的循环状态会被高频重复行为占满，偏置后续读出。**这个现象和 agent memory 的 collapse 是同构的**
- [Memory Layer](https://arxiv.org/abs/2607.25110) 把 serving 时的 in-model cache 纳入训练闭环，消除训练/服务表示不一致

**第三代：参数化记忆与稀疏激活。** MSN 之外，还有 Climber 的推荐模型 scaling law、以及 HSTU / WHALE / OneRec 这条生成式推荐 scaling 路线。这一支的记忆是**模型内部状态**，不是外部资产。

**第四代：语言化、可编辑、可演化的记忆（2026 下半年集中冒出来，最贴近 agent memory）。** 这批最有价值：

- [**Prediction Is Not Memory**](https://arxiv.org/abs/2607.24798) ——标题就是你的命题。它指出常见更新管线**把"预测一次交互"和"决定它是否该写进画像"混为一谈**，于是把瞬时情境、探索、曝光、短期满足都当成稳定偏好写进了持久状态。解法是双时间尺度的门控写入
- [CALMRec](https://arxiv.org/abs/2607.23647) 更进一步：当下的 LLM 推荐把**持久偏好、瞬时意图、曝光诱导行为**坍缩进同一个 profile，造成反馈回路（重复曝光被当成偏好、即时点击压过延迟满足）。主张因果对齐的语言记忆
- [RECAP](https://arxiv.org/abs/2607.15730)（RecSys'26）指出画像生成器大多是**开环**的——能流畅总结过去却不被训练去改善未来推荐，于是做流式闭环优化
- [rEDMRec](https://arxiv.org/abs/2608.18952) 把 LLM 推理蒸馏成**可编辑的经验记忆**，解决"推理只被消费一次就丢弃"
- [AtomRec](https://arxiv.org/abs/2609.04882) evolving atomic memory，反对把用户/物品压成粗摘要
- [VikingMem](https://arxiv.org/abs/2605.29640)（VLDB'26）把记忆当**数据库管理系统**来做——memory base management system
- [TIDE](https://arxiv.org/abs/2609.37544) 直接用推荐反馈（曝光/点击/转化）驱动 agent memory 演化，并提出 Memory Evolution Gain 指标；它明确点出这类信号**延迟、噪声、被人群与投放混淆、且多条记忆共同作用导致归因困难**
- [RankEvolve](https://arxiv.org/abs/2609.39551) 已经是"用自动研究 harness 演化排序模型"了，和 RSI 直接接壤

## 三、两个领域的结构对照

|维度|推荐系统|Agent / RSI|
|---|---|---|
|记忆单位|用户 × 交互，海量、同构|系统 × 轨迹，异构（记忆/技能/工具/参数）|
|监督信号|有即时标签，但噪声大、延迟、受曝光混淆|多半无标签，需要验证器或执行锚定|
|写入触发|默认全写（每次交互都是样本）|选择性写（反思/成功后固化）|
|载体|embedding、参数化记忆、画像文本|文本记忆、SKILL.md、LoRA|
|失效模式|兴趣漂移、曝光偏差、反馈回路、state sink|能力侵蚀、记忆膨胀、自我污染、skill misevolution|
|时间尺度|小时/天级，离线+近线|秒/任务级，在线即时写|
|评估|AUC/GAUC/线上指标|任务成功率/基准/过程级指标|

**最本质的差别**：推荐系统默认把记忆当作**特征或状态**，策略是独立的、可反复重训的；而 agent 系统倾向于把记忆**直接当成策略的一部分**（写进去就影响下一步行为）。所以你在 RSI 里看到的失效（memory reward inflation、capability collapse、skill misevolution），在推荐里被更早地识别成了"反馈回路"和"偏差"，因为推荐有真实标签可以证伪。

## 四、关于"保留记忆，但不把记忆当成策略本身"

我认为这个直觉是对的，而且两个领域各自缺一半：**推荐有"写入门控"的思想但缺"记忆治理"；RSI 有"记忆治理"的紧迫性但缺"可信信号"**。

可以试着把它拆成三层，这是我读下来觉得最能统一两个领域的框架：

**证据层（episode / trace）** —— 只记录，不参与决策。推荐里对应原始行为日志，RSI 里对应轨迹。这一层的原则是**只增不改**。

**抽象层（profile / skill / schema）** —— 需要**写入门控**。这里两个领域已经给出了同一个答案：_预测与持久化必须解耦_（Prediction Is Not Memory），_写入前先认证作用范围_（Scope Before You Persist 2609.29144，RSI 侧），_把持久偏好与瞬时光滑分离_（CALMRec）。RSI 侧的对应物是 GRASP 的门控回归感知、ORC 的执行锚定闸门。

**策略层** —— 只通过**可验证信号**与抽象层耦合，不直接读取记忆内容。推荐侧的对应是"记忆作为可替换 substrate"（Memory Layer、VikingMem、记忆即中间件）；RSI 侧的对应是 Memory as Middleware（2609.32091）、证据闸门式 harness（2609.27612）。

由此得到一条可能通用的判据：**记忆可以影响"看什么"，但不应该直接决定"做什么"**。一旦经验被提升为指令（trajectory poisoning、SkillJack、EVOMAL 攻击的正是这个提升过程），记忆就变成了策略，风险随之从"答错"升级为"永久错"。

## 五、几个我认为值得做的缝合点

1. **把 TIDE 的延迟反馈归因搬到 agent memory**。推荐领域对"延迟、噪声、混淆、多因一果"的信号处理有成熟工具箱，而 RSI 侧的 memory reward inflation 恰恰卡在归因上——这是最直接的可迁移点。
2. **把 dual-timescale gating 移植成 agent 的写入门控**。Prediction Is Not Memory 的双时间尺度结构，几乎可以原样映射到"何时把一次成功轨迹固化成 skill"。
3. **样本级 token ↔ 轨迹级 token 的对照研究**。Sample Is Feature 把样本 token 化，RSI 侧的 Experience Graphs / Tree-of-Experience 把轨迹结构化——两者在做同一件事，但社区互不知晓。
4. **SinkRec 的 semantic state sink 与 agent 的 capability collapse 可能是同一个数学现象**（压缩状态被高频模式占满、长尾被挤掉）。这个如果成立，会是一个很有分量的结论。
5. **跨领域基准**：把推荐侧的 lifelong 设定（ChronicleRec、SequenceO1）与 agent 侧的流式基准（AgentStream、FinEvo-Bench）对齐，共同考察"记忆写入是否可逆、可重建"。
